## Quick Start for Operators

### Deployment (5 steps)

1. **Review checklist** (5 min)
   ```bash
   cat docs/DEPLOYMENT_GUIDE_1.0.md | grep -A 50 "Pre-Deployment Checklist"
   ```

2. **Set environment variables** (5 min)
   ```bash
   export GENIE_JWT_SECRET="<256-bit-hex>"
   export GENIE_CSRF_SERVER_SECRET="<256-bit-hex>"
   export GENIE_KEK_BASE64="<base64-32-bytes>"
   export GENIE_DB_DSN="postgres://user:pass@host/genie?sslmode=require"
   ```

3. **Deploy** (10 min)
   ```bash
   # Docker Compose
   docker-compose up -d
   
   # OR Kubernetes
   kubectl apply -f k8s/genie-deployment.yaml
   ```

4. **Verify health** (2 min)
   ```bash
   curl http://localhost:8080/healthz
   curl http://localhost:8080/readyz
   bash docs/post-deployment-verification.sh
   ```

5. **Monitor** (ongoing)
   - Liveness: `/healthz` every 10s
   - Readiness: `/readyz` every 5s
   - Metrics: `/metrics` (Prometheus scrape)
   - Logs: structured JSON format

## Security Verification Checklist

**Before going live**, verify:

- [ ] **CSRF Protection**
  ```bash
  # Should return 403 (CSRF token required)
  curl -X POST http://localhost:8080/v1/orders \
    -H 'Authorization: Bearer <token>'
  ```

- [ ] **HttpOnly Cookies**
  ```bash
  # Login should return Set-Cookie with HttpOnly
  curl -i -X POST http://localhost:8080/v1/users/login \
    -d '{"email":"test@test.com","password":"test"}' \
    | grep Set-Cookie
  # Should contain: HttpOnly; Secure; SameSite=Strict
  ```

- [ ] **Security Headers**
  ```bash
  # Should return all 8 headers
  curl -I http://localhost:8080/v1/orders \
    | grep -E 'Content-Security-Policy|X-Frame-Options|Strict-Transport'
  ```

- [ ] **Error Sanitization**
  ```bash
  # 500 error should not expose internal details
  curl http://localhost:8080/v1/invalid \
    | grep -v 'password\|database\|secret'
  # Should only show generic message + trace ID
  ```

- [ ] **Database Backup**
  ```bash
  pg_dump -Fc -U genie genie > /backups/genie-prerelease.dump
  # Restore test: pg_restore -d test_genie /backups/genie-prerelease.dump
  ```

## Breaking Changes for Clients

### Migration Required

**Old Code (Phase 1)**:
```javascript
const response = await fetch('/v1/users/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password })
})
const { token } = await response.json()
// Store token in localStorage
localStorage.setItem('auth_token', token)

// Use in requests
const result = await fetch('/v1/orders', {
  headers: { 'Authorization': `Bearer ${localStorage.getItem('auth_token')}` }
})
```

**New Code (Phase 2)**:
```javascript
const response = await fetch('/v1/users/login', {
  method: 'POST',
  credentials: 'include', // IMPORTANT: send cookies
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password })
})
// JWT stored in Set-Cookie (HttpOnly) - client cannot access

// Get CSRF token from response header (for mutations)
const csrfToken = response.headers.get('X-CSRF-Token')

// Use in requests (cookie sent automatically)
const result = await fetch('/v1/orders', {
  method: 'POST',
  credentials: 'include', // IMPORTANT: send cookies
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-Token': csrfToken // REQUIRED for POST/PUT/DELETE
  },
  body: JSON.stringify({ ... })
})
// New CSRF token received in response header (rotation)
```

### Key Changes

1. **credentials: 'include'** required in all fetch calls
2. **No localStorage** — JWT in HttpOnly cookie only
3. **X-CSRF-Token header** required for POST/PUT/DELETE
4. **Response header** contains new CSRF token (rotation)
5. **SameSite=Strict** — no cross-site cookie transmission

### Migration Timeline

- **Immediate (now)**: Deploy new backend (backward compatible)
- **Week 1-2**: Update web clients (50% adoption target)
- **Week 2-3**: Update mobile clients (>90% adoption target)
- **v1.1 (June 2027)**: Remove bearer token support

**Issue**: Application won't start
- Check: GENIE_JWT_SECRET, GENIE_DB_DSN, database connectivity
- Reference: DEPLOYMENT_GUIDE_1.0.md → Troubleshooting
